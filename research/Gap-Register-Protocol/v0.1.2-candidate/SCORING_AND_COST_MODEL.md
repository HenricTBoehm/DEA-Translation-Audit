# Scoring and cost · prospective contract

One response has an action in RELEASE, BLOCK_CONFLICT, BLOCK_UNDETERMINED, INVALID, NO_DECISION, a native status for audit, and an optional structured evidence claim. The assessor records proof as VERIFIED, REJECTED, UNVERIFIED or NONE. For RELEASE verify scoped replay plus closure, for BLOCK_CONFLICT verify the constructive witness, for INVALID verify an admissible contradiction, and for BLOCK_UNDETERMINED verify the cited missing scope or proof. Proof assessment is independent of the reported verdict. NO_DECISION has no proof. A genuine proved abstention differs from unclassified DENY, implementation errors or no execution. Keep unclassified hold as NO_DECISION with native denial in the log. Separately distinguish NOT_IMPLEMENTED, NOT_TESTED, EVIDENCE_MISSING, timeouts and malformed outputs. Implementation failure on a scheduled runnable row contributes NO_DECISION. A whole experiment blocked before starting has NOT EXECUTED rates, without a fictitious set of responses.

| Axis | Count, denominator and consequence |
|---|---|
| S1 justified release | RELEASE on justified CLEAR / all CLEAR. False hold is its complement, including invalid, errors and abstention. |
| S1 unjustified release | RELEASE on each of justified CONFLICT, UNDETERMINED, INVALID / the corresponding category; also aggregate over all non-CLEAR. |
| Truth-relative | Releases on actual CONFLICT / actual CONFLICT; releases on actual MODEL_INVALID / actual MODEL_INVALID; holds on actual NO_CONFLICT / actual NO_CONFLICT, with no assumption that all were justified to release. Report separately from S1 and isolate X-TRUST. |
| S2 diagnosis | Exact response and verified correct response / all cases; separately verified clearance, witnessed CONFLICT, verified abstention / respective justified categories. |
| S2 contradiction | Non-INVALID on justified INVALID / justified INVALID; INVALID on justified non-INVALID / justified non-INVALID; missed actual contradiction / actual MODEL_INVALID. Report any correct INVALID with wrong or unverified proof separately. |
| S2 accusations | BLOCK_CONFLICT outside justified CONFLICT / justified non-CONFLICT; BLOCK_CONFLICT with proof other than VERIFIED / all reported BLOCK_CONFLICT. Count proofless lucky hits explicitly. |
| S2 no decision | NO_DECISION / all scheduled runnable requests. |
| S3 fidelity | PASS/FAIL/UNDETERMINED/NOT EXECUTED per unique wire view and per tested adapter or allowed source access; equality of canonical input, completeness meaning and prohibited-access audit required for PASS. Unverified corpus access or enrichment disqualifies the row/profile from differential claims. |
| S4 premises | Same rows by independently assessed SUPPORTED/OPEN/CONTRADICTED/NOT EXECUTED. Also count verified, rejected, unverified or absent authentic issuer assertions over all relevant assertions and independently supported/contradicted/open content over all relevant assertions. For B report a cross-table of actual support by each reported premise status, especially accepted false or missing attestations. |

Use exact numerators and denominators with no percentage for an empty set. Report all rows, the unique-evidence view for S1/S2/S3, and the separate premise attacks. Twins are valid executions but not two independent pieces of decision evidence. Truth-relative counts use actual executions. Track disagreement/mapping failures over twins prospectively. Check per-case results before aggregate comparisons. Maintain ordinary labels and joint cells in the raw assessor record. `scoring.py` implements the core case/view counters on assessed rows. Per-stratum instrumentation, proof adapters and receipt-level reporting remain preconditions for a real comparison.

Always-permit, always-deny, always-invalid, proofless-conflict and NO_DECISION are mandatory negative controls. A high abstention rate can improve one safety counter while failing justified clearance and diagnostics. Preserve false releases, witness accuracy and premises as distinct higher-priority obligations. Never trade a safety-critical violation for a shorter policy or faster runtime.

## Costs kept separate

The first synthetic comparison can measure nonblank noncomment lines of policy, adapter and custom semantic code separately (record language, generated lines and bundled dependency boundaries), configured versus L3 effort in person-minutes, case capture requests and observed capture latency, synthetic issuer and monitor operations/person-minutes, and CPU/wall time and peak resident MiB on the pinned image. For runtime, perform one warm-up and ten measured runs, report median/range and failures separately, and record whether startup is included. Measure actual human setup/review time if recorded by task logs. Trust assumptions and boundaries are a qualitative ledger (issuer, observers, access, completeness and revocation), not a fungible number. Real issuer behavior, actual organizational burden and field deployment remain NOT EXECUTED unless separately observed. Untimed or omitted measurements are NOT EXECUTED. Costs from the present oracle runner are reproduction data only.
